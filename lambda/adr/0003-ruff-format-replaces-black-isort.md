# ADR-0003: Ruff format заменяет black + isort

## Контекст

BaseLar v0.2.0 использует три инструмента для форматирования и сортировки импортов:

- `black` — форматирование кода
- `isort` — сортировка импортов
- `ruff check` — линтинг, включая правило `I` (isort)

Проблемы:

1. **Дублирование.** `ruff` уже содержит правило `I`, функционально
   эквивалентное `isort`. Настройки в `[tool.isort]` и
   `[tool.ruff.lint.isort]` дублируются и могут расходиться.
2. **Лишняя зависимость.** `ruff format` (стабилен с 2024) совместим с
   `black` и покрывает форматирование. Держать `black` отдельно — лишняя
   зависимость и шаг CI.
3. **Три инструмента вместо одного** увеличивают время CI, поверхность
   ошибок и количество конфигов.

## Решение

Перейти на единый тулинг:

- **`ruff format`** — форматирование (заменяет `black`).
- **`ruff check --fix`** — линтинг и автофикс, включая `I` (заменяет `isort`).

Удалить:

- Зависимости `black`, `isort` из `[project.optional-dependencies].dev`.
- Секции `[tool.black]`, `[tool.isort]` из `pyproject.toml`.
- Шаги `black --check`, `isort --check-only` из CI.

Добавить:

- `[tool.ruff.format]` — при необходимости (по умолчанию совместим с black).
- `make format` → `ruff format` + `ruff check --fix`.
- `make format-check` → `ruff format --check`.
- `make check` → `format-check` + `lint` + `lint-imports` + `test`.
- `make ci` → алиас `make check`.

## Альтернативы

1. **Оставить black + isort (статус-кво).** Отвергнуто: дублирование
   с `ruff`, три инструмента вместо одного.
2. **Убрать `I` из ruff, оставить `isort`.** Отвергнуто: `ruff` с `I`
   быстрее и не требует отдельной секции конфига. `isort` как отдельный
   инструмент избыточен.
3. **Оставить `black` + `ruff` без `isort`.** Отвергнуто: `black` не
   сортирует импорты, `ruff check --fix` с `I` это делает — `black`
   остаётся лишним.

## Последствия

- (+) Один инструмент (`ruff`) для форматирования, сортировки и линтинга.
- (+) Меньше зависимостей, быстрее CI.
- (+) Один конфиг (`[tool.ruff]`) вместо трёх.
- (−) `ruff format` может в редких случаях форматировать иначе, чем
  `black`. Для нового шаблона это неважно; для downstream-проектов,
  которые уже используют `black` — при обновлении шаблона нужно решить,
  мигрировать ли (рекомендуется).
- (−) Разработчикам нужно привыкнуть к `make format` вместо
  `black`/`isort`.

## Связь с предыдущими ADR

Не затрагивает ADR-0001, ADR-0002. Только тулинг.
