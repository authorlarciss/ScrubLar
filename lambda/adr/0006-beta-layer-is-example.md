# ADR-0006: Beta-слой — пример, не догма

## Контекст

ADR-0002 ввёл модульную архитектуру и `public/` + `_internal/`.
BaseLar поставляет в `beta/` интерфейсы и примеры реализации:

- `IProcessor`, `IWorkflow`, `PipelineWorkflow` — пайплайн обработки.
- `IEventBus` — асинхронная шина событий.
- `IEvent` (в `alpha/`) — marker class для событий.

TirLar v0.1.0 (первый downstream-проект на BaseLar) удалил все четыре
через ADR-0007:

- Движок игры — машина состояний, не пайплайн. `IProcessor` с `Any`
  в сигнатурах несовместим с mypy strict и типизированным `BattleState`.
- `IEventBus` не нужен: события обрабатываются синхронно.
- `BattleEvent` — discriminated union, а не marker class `IEvent`.

Это правильное применение шаблона: `beta/` — scaffold для одного класса
задач (pipeline), а не универсальный слой. Но в BaseLar нигде не
сказано, что отклонение — норма. Читатель `CONTRIBUTING.md` видит
«модули независимы, интерфейсы в провайдерах» и может решить, что
удаление `IProcessor` — нарушение.

## Решение

Зафиксировать явно: **`beta/` — пример для pipeline-задач. Если домен
проекта — не pipeline, удаление scaffold'а и замена своим паттерном —
норма, а не нарушение.**

Правила:

1. **Стандартные интерфейсы `beta/` опциональны.** `IProcessor`,
   `IWorkflow`, `PipelineWorkflow`, `IEventBus`, `IEvent` — примеры.
   Проект может их оставить, заменить или удалить.

2. **Удаление фиксируется ADR.** Как TirLar сделал с ADR-0007.
   Причина: следующему читателю нужно понимать, почему `IProcessor`
   нет, а не искать, не забыли ли.

3. **Архитектурные границы ADR-0002 сохраняются.** Удаление scaffold'а
   не отменяет `public/` + `_internal/`, resolver pattern, связь через
   `psi.contracts`. Меняется содержимое `beta/`, не правила.

4. **`psi.bootstrap` собирает то, что есть.** Если проект удалил
   `BetaResolver.make_workflow`, bootstrap не должен его вызывать.
   Шаблонный `build_application()` — тоже scaffold, его переписывают
   под домен (TirLar переписал).

5. **`alpha/` остаётся алфавитом.** Даже если `IEvent` удалён, `alpha/`
   содержит типы проекта. Пустой `alpha/` — сигнал, что типы разошлись
   по другим модулям; это отдельный разговор, не автоматическое
   следствие удаления scaffold'а.

## Что НЕ означает это решение

- Не «можно игнорировать архитектуру». Границы `public`/`_internal`,
  resolver, contracts — обязательны. Опционален только **содержимое
  scaffold'а**.
- Не «каждый проект с чистого листа». Большинство проектов оставят
  `IProcessor`/`IWorkflow` — они подходят для пайплайнов (обработка
  документов, ETL, конвейеры). TirLar — исключение (state machine).
- Не «удалять без ADR». Молчаливое удаление — то же, что молчаливое
  нарушение. ADR фиксирует «мы знаем, что делаем».

## Альтернативы

1. **Добавить state-machine паттерн в BaseLar** (`IStateMachine`,
   `ITransition`). Отвергнуто: BaseLar превращается в «сборник
   паттернов», что противоречит принципу «не создавать пустые
   директории на будущее» (CONTRIBUTING, п. 4.5). Один паттерн как
   пример + явное разрешение отклоняться — достаточно.

2. **Оставить как есть, без ADR.** Отвергнуто: TirLar уже удалил
   scaffold через ADR-0007. Без ответного ADR в BaseLar читатель
   не поймёт, что это норма.

3. **Удалить scaffold из BaseLar совсем.** Отвергнуто: pipeline —
   самый частый паттерн в экосистеме (ScrubLar: детектор → маскер →
   отчёт — это пайплайн). Scaffold полезен большинству.

## Последствия

- (+) Проекты с не-pipeline доменом не чувствуют вины за удаление.
- (+) `beta/` остаётся полезным для большинства (pipeline).
- (+) ADR-0007 TirLar получает ответный ADR в BaseLar — дискуссия
  замкнута.
- (−) Читатель `CONTRIBUTING.md` должен теперь держать в голове:
  «scaffold опционален, границы обязательны». Формулировка в
  CONTRIBUTING должна быть явной.
- (−) Если downstream удалил scaffold, но забыл ADR — это не поймать
  автоматически. Правило «удаление через ADR» — code review, не
  import-linter.

## Связь с предыдущими ADR

- ADR-0002 (архитектура) — не отменяется, дополняется.
- ADR-0007 from TirLar (адаптация beta) — получает ответный ADR в BaseLar.
