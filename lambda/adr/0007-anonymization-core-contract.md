# ADR-0007: Контракт ядра обезличивания

## Контекст

ScrubLar должен обнаруживать ПДн в тексте и заменять их на плейсхолдеры.
Ядро — детектор и маскер. До кода фиксируем контракт: что принимают,
что возвращают, какие инварианты держат. Иначе на второй итерации
(добавление типов ПДн, смена стратегии маскировки) придётся переписывать
интерфейсы.

## Решение

**Две чистые функции, два типа результата.**

    def detect(text: str, config: DetectionConfig) -> DetectionReport: ...
    def mask(text: str, report: DetectionReport) -> MaskResult: ...

1. **Детерминизм.** При одинаковых `(text, config)` результат одинаков.
   NER-модель детерминирована при фиксированной версии; версия модели
   входит в `DetectionConfig`. Глобальный `random` не используется.

2. **Иммутабельность.** `PIIEntity`, `DetectionReport`, `MaskResult` —
   `frozen dataclass`. `detect` и `mask` не мутируют вход.

3. **Нет I/O в ядре.** `alpha`, `beta`, `iota`, `epsilon` не импортируют
   `print`, `input`, `time`, `sys`. Документ приходит как `str`.
   Файловый ввод-вывод — в `delta`, HTTP — в `gamma`.

4. **Маскировка — замена на `<ТИП_N>` с локальным маппингом.**
   `MaskResult.mapping: Mapping[str, PIIEntity]` — только в памяти.
   Ничего не пишется на диск. `restore` (v0.2) — отдельная функция,
   не часть MVP.

5. **Структурированные ПДн — regex + контрольные суммы.** СНИЛС, ИНН,
   паспорт, телефон, email. Контрольные суммы — обязательны: без них
   regex даёт ложные срабатывания на случайных числах.

6. **NER — отдельный сервис в `epsilon`.** ФИО детектируется NER-моделью
   (GLiNER или ruBERT, выбор — отдельной iota после теста на 10 примерах).
   `IDetector` в `beta` собирает результаты: structured из `iota`, NER
   из `epsilon`, объединяет, разрешает пересечения.

7. **`DetectionReport` — список сущностей с позициями и типами.**
   Не модифицированный текст. Это позволяет: (а) показать превью с
   подсветкой до маскировки, (б) тестировать детектор без маскера,
   (в) менять стратегию маскировки (звёздочки, плейсхолдеры, хеши)
   без переписывания детектора.

## Альтернативы

1. **Один класс `Anonymizer` с методами `detect` и `mask`.**
   Отвергнуто: детектор и маскер тестируются по отдельности; один
   класс тянет за собой обе зависимости.

2. **Немедленная маскировка без `DetectionReport` (streaming).**
   Отвергнуто в MVP: превью с подсветкой требует показать найденное
   до маскировки. Для CLI-версии streaming был бы ок, для веб — нет.

3. **Пайплайн через `IProcessor`/`IWorkflow` (BaseLar scaffold).**
   Отвергнуто: пайплайн — линейная последовательность шагов с `Any`
   в сигнатурах. Наш случай — две чистые функции с типизированными
   входами-выходами. Scaffold удаляется (по ADR-0008 BaseLar, удаление
   scaffold через ADR — норма).

4. **Хранить маппинг на диск для восстановления.**
   Отвергнуто: маппинг содержит ПДн в открытом виде. На диске — только
   очищенный документ + отчёт без значений ПДн. Восстановление (v0.2)
   будет через отдельный режим с явным подтверждением пользователя.

## Последствия

- (+) Детектор и маскер тестируются отдельно.
- (+) Превью с подсветкой возможно без переписывания ядра.
- (+) Стратегия маскировки меняется без изменения детектора.
- (+) Маппинг в памяти — снижает риск утечки через файлы.
- (−) Два прохода по тексту (`detect` + `mask`) — `O(2N)`. Для
  документов до 100 КБ несущественно.
- (−) NER в отдельном модуле `epsilon` — дополнительная сложность
  сборки в `psi.bootstrap`. Оправдано: модель тяжёлая, `beta` не
  должен зависеть от `transformers` напрямую.

## Связь с предыдущими ADR

- ADR-0002 (BaseLar): архитектура модулей — сохраняется.
- ADR-0008 (BaseLar): beta-слой — пример, не догма. Удаление
  `IProcessor`/`IWorkflow`/`IEventBus`/`IEvent` в ScrubLar — по
  этому ADR.
