# ADR-0011: Методология оценки качества детектора

## Контекст

Нужны цифры recall/precision для курсовой и для проверки ADR-0008
(Natasha на реальном наборе). Первая итерация генератора дала 100%
по всем типам — это smoke test, а не benchmark: генератор создавал
текст ровно с теми ПДн, которые ищет детектор, без падежей и
false-positive кандидатов.

## Решение

Двухуровневая оценка на синтетическом наборе из 50 документов (seed=42):

**Clean (25 документов, чётный idx).** ПДн в именительном падеже,
стандартные форматы. Smoke test: пайплайн работает end-to-end.
Ожидаемый результат: recall/precision 1.0. Если не 1.0 — баг.

**Adversarial (25 документов, нечётный idx).** Честная оценка:
- ФИО в родительном/дательном падеже (6 фиксированных примеров:
  «Иванова Ивана Ивановича», «Петровой Марии Сергеевны» и т.д.).
- 1–2 false-positive кандидата в каждом: «ООО «Ромашка»»,
  «ООО «Иванов и партнёры»», «приказ № 1234567», «дата 12.03.1985»,
  «ИНН 0000000000», «СНИЛС 123-456-789 00», «версия 8.999.123».

**Метрика:** overlap-based (TP = предсказанный span пересекается с
ground truth того же типа). Exact match занижает ФИО в 2–5 раз
(отчество и инициалы опциональны) — это уже проверено в ADR-0008.

**Пороги в `test_metrics.py`:**
- overall recall ≥ 0.90, precision ≥ 0.85 (гипотеза курсовой);
- structured (5 типов) ≥ 0.95 каждый;
- NAME recall ≥ 0.85, precision ≥ 0.80 (NER статистический,
  известное ограничение с компаниями).

## Результаты (seed=42, 50 документов)

| Тип | Precision | Recall | F1 |
|---|---|---|---|
| NAME | 0.862 | 1.000 | 0.926 |
| PHONE | 1.000 | 1.000 | 1.000 |
| EMAIL | 1.000 | 1.000 | 1.000 |
| SNILS | 1.000 | 1.000 | 1.000 |
| INN | 1.000 | 1.000 | 1.000 |
| PASSPORT | 1.000 | 1.000 | 1.000 |

Overall recall 1.0, precision ~0.93.

**Найдено adversarial-тестом:** `inn10_valid("0000000000")` возвращал
True (сумма весов × 0 = 0, check = 0). То же для SNILS/INN12.
Исправлено: `len(set(digits)) == 1 → False`. Реальные ИНН/СНИЛС
не бывают из одинаковых цифр.

## Ограничения

- **Синтетика, не реальные документы.** Ground truth известен по
  построению, но тексты — шаблоны. Реальные документы содержат
  больше вариативности (опечатки, нестандартные форматы, смешение
  языков). Реальный benchmark — 20–30 вручную размеченных
  обезличенных документов — в v0.2.
- **6 падежных примеров, не полная морфология.** Реальные ФИО в
  падежах могут дать хуже результат. Natasha справилась с 6
  фиксированными формами — это не гарантия для всех.
- **FP-кандидаты — 8 фиксированных.** Реальные ложные срабатывания
  (номера домов, коды регионов) не покрыты.

## Альтернативы

1. **Только clean.** Отвергнуто: 100% — не ответ на защите.
2. **Только adversarial.** Отвергнуто: без clean нельзя отличить
   баг от ограничения NER (если clean не 100% — это баг).
3. **Вручную размеченные 20–30 документов сейчас.** Отвергнуто:
   нет времени до 31 октября. В v0.2.

## Связь с предыдущими ADR

- ADR-0007 (контракт ядра): `detect` возвращает `DetectionReport`
  с позициями — метрики считаются по спанам.
- ADR-0008 (Natasha): 15 фикстур, F1 0.966. Здесь — 50 документов,
  NAME F1 0.926. Падение — падежи и FP-кандидаты, ожидаемо.
